## 1. Purpose

Fabric provides permissioned, tamper-evident anchoring of finalized treatment-record proof. PostgreSQL remains the detailed evidence store.

## 2. Logical organizations

Minimum logical organizations:

1. `FacilityOrg` — represents participating facility-side authority.
2. `AuditorOrg` — represents independent audit authority.
3. `RegulatorOrg` — represents regulatory stakeholder authority.

A separate `SystemOrg`/operator identity may administer the demonstration network but must not be treated as a research stakeholder by default.

For a local academic deployment, multiple logical organizations may run on one machine; organizational separation must still exist in MSP identities and endorsement policy.

## 3. Network topology

Minimum development topology:
- one orderer service;
- one peer per logical organization;
- one CA per organization or an explicitly documented CA arrangement;
- one application channel for the research network;
- Fabric Gateway client access from the DLT anchor service.

Production-like experiments may expand peers/orderers only when the experimental protocol explicitly requires it.

## 4. Channel

Primary channel: `aquatrust-channel`.

The channel carries only the research ledger state required for treatment-record proof. Do not place raw wastewater telemetry on the ledger.

## 5. Chaincode

Chaincode name: `aquatrust-records`.

Minimum logical operations:
- `CreateAnchor`
- `ReadAnchor`
- `GetAnchorByRecordId`
- `GetAnchorByHash`
- `RecordCorrectionLink`
- `VerifyAnchorReference`

Chaincode must reject:
- duplicate finalized record anchors;
- malformed hashes;
- missing certificate/record identifiers;
- unauthorized state transitions;
- attempts to mutate a confirmed anchor's protected hash.

## 6. Anchor payload

```text
anchor_id
record_id
certificate_id
facility_id
event_timestamp
canonical_hash
compliance_status
signature_algorithm
signature_key_id
record_version
anchor_schema_version
```

## 7. Endorsement policy

Default research policy: a finalized anchor must receive endorsement from at least two distinct organizational identities when the local network topology supports them. The exact policy expression must be recorded in the Phase 10 completion report and test fixtures.

A single-organization local smoke test is allowed only as a development bootstrap; it is not sufficient evidence for the permissioned multi-party research claim.

## 8. Identity and certificates

- Use Fabric MSP identities.
- CA-issued identities are required for organizational participants.
- Application identities must map to the logical organization and actor role.
- Private keys must not be committed to the repository.
- Development credentials must be clearly separated from any production-like credential set.

## 9. Gateway boundary

FastAPI/domain services do not directly fabricate ledger state. A dedicated DLT adapter/anchor service invokes Fabric through a supported Gateway client API and persists the returned transaction reference.

The database must distinguish:
`pending → submitted → confirmed` and failure/reconciliation states.

## 10. DLT transaction lifecycle

```text
Finalized + signed record
        ↓
Create deterministic anchor payload
        ↓
Submit through Fabric Gateway
        ↓
Endorse/order/commit
        ↓
Receive transaction ID + commit confirmation
        ↓
Persist anchor status/reference
```

No transaction ID may be generated by the application before Fabric returns it.

## 11. Verification use

Verification compares:
1. PostgreSQL canonical hash;
2. independently recomputed SHA-256;
3. stored signature verification result;
4. Fabric anchor hash.

A matching DLT hash proves ledger consistency with the anchored hash; it does not prove that the physical measurement was correct.

## 12. Failure/reconciliation

If Fabric is unavailable:
- finalized PostgreSQL evidence remains intact;
- anchor status becomes `failed` or `reconciliation_required`;
- no fake transaction ID is stored;
- retry is idempotent;
- confirmed anchors are never duplicated for the same record.

## 13. Phase 10 environment freeze

- Gateway client version;
- Docker/Compose or orchestration version;
- organization/peer/orderer topology;

## Frozen implementation baseline
- Chaincode language: TypeScript/Node.js.
- Fabric Gateway client: Node.js/TypeScript client matching the pinned Fabric release.
- CA: Fabric CA.
- Channel: `aquatrust-channel`.
- Chaincode name: `aquatrust-records`.
- Primary anchor key: `record_id`.
- Ledger state stores compact anchor metadata and verification references, never raw high-frequency telemetry.
- All container image tags and client package versions must be recorded in the Phase 10 environment manifest.
