# AquaTrust AI — Data Provenance Specification

**Status:** AUTHORITATIVE / FROZEN  
**Version:** 2.2.1

Every imported public dataset and every simulator output must be traceable to its source and processing lineage.

## Dataset portfolio policy

AquaTrust AI uses a versioned multi-source dataset portfolio. The current source pool is governed by `MASTER/DATASET_PORTFOLIO_SPECIFICATION.md`. Dataset choice is not hard-coded into downstream services.

The existing Bangalore and Indian water-quality datasets are retained as legacy/current-state assets and must not be assumed to be the permanent master research dataset.

## Source separation invariant

Observations from different source datasets or physical facilities must not be row-wise combined to fabricate a single treatment event. Cross-source use must preserve source identity and be justified by the preprocessing, ML or experiment methodology.

A same-date inlet/outlet observation from the same facility is still not automatically one physical sample/event when the source defines different sampling windows or methods.

## Source-record classification

Every source record entering preprocessing must be classified as one of:

- `measurement` — an observed wastewater measurement eligible for canonicalization;
- `regulatory_limit` — a stated standard/limit, not an observed measurement;
- `narrative_or_metadata` — descriptive/report content that is not a measurement.

Only `measurement` records may enter the canonical observed-reading pipeline.

`regulatory_limit` records must never be used as ML training observations or represented as measured wastewater values.

## Data origin

Every standardized or generated reading must be distinguishable as:

- `observed` — originating from a public/real source observation; or
- `simulated` — generated by the AquaTrust simulator.

Simulator records additionally retain the source dataset lineage used to construct their input.

## Dataset provenance fields

Every dataset manifest must retain:

- `dataset_id`: immutable UUID
- `dataset_name`
- `source_name`
- `source_reference`
- `retrieval_date`: ISO-8601 UTC date
- `license`
- `original_filename`
- `source_sha256`
- `processing_version`
- `processing_timestamp`
- `transformations_applied`
- `excluded_record_count`
- `exclusion_reasons`
- parameter coverage
- unit mapping
- timestamp semantics
- facility/stage semantics
- record-type classification
- known limitations

Agents must never invent missing provenance. Unknown values remain explicitly unknown until verified.

## Record lineage

For observed records, provenance must retain:

- `data_origin = observed`
- `dataset_id`
- `source_row_reference` when available
- `processing_version`
- source record classification = `measurement`
- facility/source identity where available.

For simulated records, provenance must retain:

- `data_origin = simulated`
- `scenario_id`
- `simulation_seed`
- `processing_version`
- `source_dataset_ids[]` when source-derived;
- `source_row_references[]` or distribution/profile references when available.

A simulated reading may have multiple source datasets in `source_dataset_ids[]` when the simulation methodology explicitly pools parameter distributions or other source-derived inputs. This does not authorize row-wise fabrication of a physical treatment event.

## Reproducibility

A processing run is reproducible when the same source checksum(s), processing version, transformation configuration, simulator scenario and seed produce the same standardized/simulated output, subject to documented infrastructure-level nondeterminism.

## Experiment snapshot

Every measured experiment must freeze:

- dataset manifest checksum;
- per-source checksums;
- processed-data checksums;
- processing version;
- simulator configuration;
- workload manifest;
- random seeds.

## Prohibition

Agents must not:
- invent dataset URLs, licenses, retrieval dates or provenance claims;
- silently pair inlet/outlet records as one event;
- use regulatory limits as observations;
- hide source lineage behind a generic dataset label;
- alter a source after the experiment snapshot without creating a new snapshot/version.
